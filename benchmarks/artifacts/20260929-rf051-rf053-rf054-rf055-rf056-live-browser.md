# RF-051/RF-053/RF-054/RF-055/RF-056 Live Browser Evidence

Internal-only evidence; release-facing behavior is recorded in
`release-notes/20260929-web-messaging-event-coalescing.md`. No API credentials,
conversation names, or message bodies are included here.

## Method and safety boundary

The authenticated browser used the current checkout's `web/build` assets on
the existing `http://127.0.0.1:5030` origin and sent API `GET` requests to the
existing local test daemon. Playwright fulfilled document and asset requests
from the build directory; it started no listener, changed no daemon process,
and added no product port. A browser route blocked every API method other than
`GET`, `HEAD`, and `OPTIONS` before it could reach the daemon. Per-path read
budgets bounded the browser audits. The current build was `index-Bb5S2pcd.js`
with index SHA-256
`715de639900ed89c91f4eebe3dd8b7eb7aa7d4b7aacf1f36cf201109d12b7d72`.

## Event-burst observation and coalescing

Before the current event-refresh throttle, a short read-only visit to the
daemon's embedded Web bundle received 342 `message.received` frames plus room
activity frames and issued 119 successful `GET`s apiece to conversations,
joined rooms, pods, and pod discovery in about 1.6 seconds. This identified
repeated full workspace hydration as a real cost of event bursts.

The current Web bundle was then exercised with two mocked event-feed sockets.
They delivered 100 synthetic frames in total (25 message events and 25 room
events to each socket); no synthetic frame was sent to the daemon. The live API
received exactly two reads apiece for conversations, joined rooms, and pods:
the initial workspace load and one coalesced refresh. Pod discovery received
zero calls for this runtime. No reads exceeded the per-path budget, and no API
write was attempted. The one-second event throttle also reschedules while an
existing hydration is still active and clears its timer when the workspace
unmounts.

## Visibility cadence

The current Web bundle rendered `/searches` against the live test API. A
main-world `visibilitychange` probe exercised the same
`document.visibilityState` value read by the Web pollers:

| Window | Conversation activity | Room activity | Mesh transport | Transfer speeds |
| --- | ---: | ---: | ---: | ---: |
| Visible, 5.2 seconds | 1 | 1 | 3 | 3 |
| Hidden, 10.6 seconds | 0 | 0 | 0 | 0 |
| Resumed, 1.4 seconds | 1 | 1 | 1 | 1 |

Every counted response returned HTTP 200. This directly exercises RF-051's
navigation-activity pause/resume and RF-053's two-second footer cadence. One
other API read was fulfilled locally with HTTP 429 after the audit's per-path
cap of four; none of the four measured endpoints was capped.

## Cursor and cancellation

The read-only test database had one saved conversation with existing history
and a usable cursor. The current Web bundle's initial conversation read
returned HTTP 200 with a cursor; the next five-second poll included `since`
and also returned HTTP 200. The conversation was marked unread, so the audit
blocked two attempted acknowledgement `PUT`s in the browser before either
could reach the daemon.

For RF-056, the audit delayed the next conversation read, navigated within the
SPA to `/searches`, and observed the still-pending request fail with
`net::ERR_ABORTED`. The route changed successfully, no response arrived for
that request, and no API mutation reached the daemon.
